# Механизм тегирования данных

## Цель
Автоматическая классификация и маркировка конфиденциальных данных при их вводе, хранении и передаче. Теги используются для применения политик доступа, шифрования, маскирования и контроля срока жизни данных.

## Схема тегов

### Категория (обязательный тег)
| Тег | Описание | Примеры |
|---|---|---|
| `PII` | Персональные данные | ФИО, дата рождения, телефон, email, адрес |
| `MEDICAL` | Медицинские данные | Диагноз, анамнез, назначения, результаты анализов |
| `FINANCIAL` | Финансовые данные | Платежи, зарплата, налоги, реквизиты |
| `AUTH` | Учётные данные | Логины, пароли, ключи |
| `INVENTORY` | Товарно-материальные ценности | Номенклатура, остатки, цены |
| `BUSINESS` | Служебные данные | Отчёты, служебная переписка |

### Уровень чувствительности (обязательный тег)
| Тег | Описание | Примеры |
|---|---|---|
| `SENSITIVITY:LOW` | Низкая — утечка незначительно влияет | Номенклатура ТМЦ |
| `SENSITIVITY:MEDIUM` | Средняя — утечка наносит умеренный ущерб | Журналы записи, плановые отчёты |
| `SENSITIVITY:HIGH` | Высокая — утечка наносит существенный ущерб | ФИО, телефон, email, платёжные данные |
| `SENSITIVITY:CRITICAL` | Критическая — утечка создаёт репутационные и юридические риски | Диагнозы, анализы, данные детей, пароли |

### Срок хранения (рекомендуемый тег)
| Тег | Срок | Применение |
|---|---|---|
| `RETENTION:1Y` | 1 год | Результаты анализов |
| `RETENTION:3Y` | 3 года | Медицинские карты (по 152-ФЗ) |
| `RETENTION:5Y` | 5 лет | Финансовые документы |
| `RETENTION:INDEF` | Бессрочно | Закрытые договоры, архивы |

### Происхождение (опциональный тег)
| Тег | Описание |
|---|---|
| `SOURCE:PORTAL` | Введено через портал пациента |
| `SOURCE:RECEPTION` | Введено сотрудником ресепшена |
| `SOURCE:DOCTOR` | Введено врачом |
| `SOURCE:LAB` | Получено от лаборатории |
| `SOURCE:1C` | Импортировано из 1С |

## Правила присвоения тегов

### Автоматическое тегирование (preferable)
| Условие | Присваиваемые теги |
|---|---|
| Пользователь вводит ФИО, телефон, email | `PII`, `SENSITIVITY:HIGH` |
| Врач сохраняет запись осмотра | `MEDICAL`, `SENSITIVITY:CRITICAL`, `SOURCE:DOCTOR` |
| Создаётся платёжный документ | `FINANCIAL`, `SENSITIVITY:HIGH` |
| Загружается результат анализа | `MEDICAL`, `SENSITIVITY:CRITICAL`, `SOURCE:LAB` |
| Создаётся номенклатура ТМЦ | `INVENTORY`, `SENSITIVITY:LOW` |

### Ручное тегирование (fallback)
- Для свободных комментариев, примечаний, файлов без структуры — оператор выбирает категорию и уровень из выпадающего списка
- Если тег не присвоен — система блокирует сохранение (должно выполняться политикой)

### Наследование тегов
- При копировании данных теги наследуются
- При агрегации (например, построении отчёта) теги наследуются от источника
- При обезличивании тег `PII` заменяется на `ANONYMIZED`

## Инструменты для реализации
- **На этапе ввода**: кастомная разметка полей в API Gateway / веб-формах
- **На этапе БД**: PostgreSQL Row-Level Security + колонка `tags jsonb`
- **На этапе ETL**: Apache NiFi + процессоры тегирования
- **На этапе контроля**: OPA (Open Policy Agent) — политики доступа на основе тегов
