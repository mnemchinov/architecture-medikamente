# Классификация данных и стратегия шифрования

## 1. Классификация данных

| Категория | Примеры данных | Состояние | Уровень чувствительности | Профиль риска |
|---|---|---|---|---|
| **Идентификационные ПДн (PII)** | ФИО, дата рождения, пол, СНИЛС, полис ОМС | At Rest / In Transit | **Высокий** | Утечка → штрафы РКН до 300 тыс. руб. (152-ФЗ), утрата доверия пациентов |
| **Контактные ПДн** | Телефон, email, адрес регистрации | At Rest / In Transit | **Высокий** | Утечка → спам-атаки, фишинг, репутационный ущерб |
| **Медицинские данные** | Диагнозы, анамнез, назначения, результаты анализов | At Rest / In Transit | **Критический** | Утечка → нарушение врачебной тайны (ст. 13 323-ФЗ), уголовная ответственность (ст. 137 УК РФ), репутационная катастрофа |
| **Платёжные данные** | Сумма, дата, способ оплаты, токен карты | At Rest / In Transit | **Высокий** | Утечка → требования PCI DSS, штрафы, chargeback-риски |
| **Учётные данные** | Логины, хеши паролей, JWT-токены | At Rest / In Transit | **Критический** | Компрометация → полный доступ к системе от имени легального пользователя |
| **Согласия на обработку ПДн** | Отметки пациента, дата, объём согласия | At Rest / In Transit | **Средний** | Утрата → невозможность доказать правомерность обработки (152-ФЗ ст. 9) |
| **Журналы аудита** | Кто, когда, к каким данным обращался | At Rest / In Transit | **Средний** | Утрата/модификация → невозможность расследования инцидентов |
| **ТМЦ и номенклатура** | Наименования, цены, остатки, поставщики | At Rest / In Transit | **Низкий** | Утечка → незначительные конкурентные потери |
| **Метрики и мониторинг** | Latency, CPU, memory, RPS | In Transit | **Низкий** | Утечка → минимальный риск (техническая информация) |

## 2. Обоснование необходимости защиты

### 2.1. Нормативные требования

- **152-ФЗ «О персональных данных»**: шифрование ПДн обязательно для всех категорий (ст. 19), требуется аттестация системы по УЗ-1/УЗ-2
- **323-ФЗ «Об основах охраны здоровья»**: врачебная тайна (ст. 13) — медицинские данные подлежат обязательной защите
- **PCI DSS**: при приёме платежей — шифрование PAN at rest и in transit
- **Приказ ФСТЭК № 21**: требования к шифрованию для ГИС ПДн (классы 2-3)
- **GDPR (для иностранных пациентов)**: шифрование как базовая мера (ст. 32)

### 2.2. Бизнес-риски

| Риск | Последствия |
|---|---|
| Утечка медицинских данных | Потеря лицензии, судебные иски, отток пациентов |
| Утечка платёжных данных | Штрафы платёжных систем, блокировка эквайринга |
| Компрометация учётных данных | Несанкционированный доступ к системе, изменение/удаление данных |
| Утрата согласий на ПДн | Невозможность доказать правомерность обработки, штрафы РКН |
| Утрата/подмена журналов аудита | Невозможность расследования, несоответствие регуляторным требованиям |

### 2.3. Репутационные риски

- Утечка диагнозов пациентов → публичный резонанс, потеря доверия к клинике
- Систематические утечки → исключение из госпрограмм (ОМС, ДМС)
- Падение стоимости бизнеса при попытке продажи/инвестиций

## 3. Стратегия шифрования At Rest

| Компонент | Механизм | Детали |
|---|---|---|
| **PostgreSQL (основная БД)** | TDE (Transparent Data Encryption) + AES-256-GCM на уровне таблиц | Прозрачное шифрование всех данных; ключ — в Vault, не на диске |
| **ClickHouse (аналитика)** | Шифрование таблиц алгоритмом AES-256 (AES_Encrypt) + шифрование дисков | Данные шифруются при записи, расшифровываются при чтении через Vault |
| **Elasticsearch (логи)** | Elasticsearch Encryption at Rest (AES-256) + Elasticseach Security | Шифрование индексов, TLS для нод |
| **Файловые хранилища/бэкапы** | pgBackRest + AES-256-GCM для бэкапов PostgreSQL; Velero + KMS для PVC | Ключ шифрования бэкапов — отдельный от ключа БД |
| **Виртуальные машины / поды** | Шифрование дисков (KMS + Ceph RBD encryption / LUKS) | Full Disk Encryption на узлах |
| **Ключи шифрования** | HashiCorp Vault + автоматическая ротация каждые 90 дней | Ключи никогда не покидают Vault; доступ — по политикам OPA |

### Генерация и ротация ключей

- Первичные ключи данных (DEK) генерируются Vault, шифруются мастер-ключом (KEK)
- KEK хранится в HSM (AWS CloudHSM / локальный HSM) — аппаратная защита
- Ротация KEK — раз в год, DEK — раз в 90 дней или при компрометации
- История ключей сохраняется для расшифровки старых данных (не менее 5 лет)

## 4. Стратегия шифрования In Transit

| Канал | Протокол | Детали |
|---|---|---|
| **Пациент → Patient Portal** | TLS 1.3 (HTTPS) + HSTS | Сертификат Let's Encrypt / коммерческий CA, автоматическое обновление cert-manager |
| **Портал → API Gateway** | TLS 1.3 + mTLS (service-to-service) | Взаимная аутентификация, отклонение неподписанных запросов |
| **Gateway → Микросервисы** | mTLS (через Istio Sidecar) | Прозрачный mTLS на уровне Service Mesh, политики авторизации |
| **Микроуслуги → БД** | TLS 1.3 + Client Certificate | PostgreSQL — sslmode=verify-full |
| **Микроуслуги → ClickHouse / ES** | TLS 1.3 (HTTPS / Native Protocol) | Native protocol ClickHouse с TLS; ES с HTTPS |
| **Внешние интеграции (лаборатория, банк, ФНС)** | TLS 1.3 (mTLS для лаборатории) | Взаимные сертификаты, валидация цепочки CA |
| **Филиалы (WAN)** | WireGuard / IPsec | Зашифрованный туннель между филиалами и центральным кластером |
| **Разработчики (CI/CD, kubectl)** | TLS 1.3 + Client Cert | Доступ строго через VPN + сертификат |

## 5. Автоматизированный контроль шифрования

| Средство | Назначение |
|---|---|
| **OPA (Open Policy Agent)** | Политика: «ни один сервис не может быть запущен без включённого mTLS» |
| **cert-manager** | Автоматический выпуск и обновление TLS-сертификатов в Kubernetes |
| **Trivy / Aqua Security** | Сканирование образов контейнеров на проблемы с TLS, устаревшие протоколы |
| **tls-scan / testssl.sh** | Периодическое сканирование endpoints на поддержку TLS 1.3, отсутствие слабых шифров |
| **Prometheus + Blackbox Exporter** | Мониторинг доступности и валидности сертификатов (оповещение за 14 дней до истечения) |
| **Kyverno** | Контроль Admission: проверка, что каждый Ingress имеет TLS, каждый Pod — NetworkPolicy |
| **Falco** | Обнаружение попыток чтения ключей из Vault вне легальных сервисов |
